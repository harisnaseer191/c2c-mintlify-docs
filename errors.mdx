# Error Handling

All API errors return a JSON body with the following structure:

```json
{
  "success": false,
  "error": "Human-readable error message",
  "code": "MACHINE_READABLE_CODE"
}
```

## HTTP status codes

| Code | Meaning |
|------|---------|
| `400` | Bad request — invalid parameters or missing required fields |
| `401` | Unauthorized — missing or invalid API key, or a missing, expired, invalid or replayed request signature |
| `404` | Not found — order does not exist or belongs to another merchant |
| `422` | Unprocessable — business rule violation (e.g., insufficient merchant balance for a withdrawal) |
| `429` | Too many requests — rate limit exceeded |
| `500` | Internal server error — contact support |

## Common error codes

| Code | Status | Description |
|------|--------|-------------|
| `UNAUTHORIZED` | 401 | Missing or invalid API key |
| `SIGNATURE_REQUIRED` | 401 | `X-C2C-Timestamp` or `X-C2C-Signature` header missing or malformed — see [Request Signing](/signing) |
| `SIGNATURE_EXPIRED` | 401 | Signature timestamp more than 5 minutes from server time |
| `SIGNATURE_INVALID` | 401 | Signature does not match, or the API key is unknown/revoked |
| `SIGNATURE_REPLAYED` | 401 | The same signed `POST` was already accepted — re-sign retries with a fresh timestamp |
| `IDEMPOTENCY_KEY_MISSING` | 400 | `Idempotency-Key` header not provided |
| `ORDER_NOT_FOUND` | 404 | Order ID does not exist or belongs to another merchant |
| `NO_ELIGIBLE_MEMBER` | 422 | No member is currently online and available for the requested wallet type and amount — retry later |
| `INSUFFICIENT_BALANCE` | 422 | Withdrawal only: your available balance cannot cover this withdrawal plus all withdrawals still in progress, including fees |
| — | 429 | More than 100 requests per minute for this API key (empty response body) |
| `INVALID_AMOUNT` | 400 | Amount is zero, negative, or exceeds configured limits |
| `UNSUPPORTED_WALLET` | 400 | Requested wallet type is not currently available |

## Reused idempotency keys

Reusing an `Idempotency-Key` is **not** an error. The API returns `200` with the order the key
originally created (and its current status) — no new order is created. See [Idempotency](/idempotency).

## Replayed signatures (401)

Each `POST` signature is accepted only once. Resending the exact same signed request — for
example, retrying with the headers you computed for the first attempt — is rejected:

```json
{
  "success": false,
  "error": "Request signature is missing, expired, or invalid.",
  "code": "SIGNATURE_REPLAYED"
}
```

Compute a new `X-C2C-Timestamp` and `X-C2C-Signature` for every retry, keeping the same
`Idempotency-Key`. See [Replay protection](/signing#replay-protection).

## Invalid callback / redirect URLs (400)

`callbackUrl`, `successUrl` and `failureUrl` must each be an absolute `http://` or `https://` URL
(max 500 characters). Any other scheme (e.g. `javascript:`, `data:`, `ftp:`) or a relative URL is rejected:

```json
{ "error": "SuccessUrl must be a valid absolute http(s) URL." }
```

## Insufficient balance for a withdrawal (422)

When you create a **withdrawal** order, the platform checks up front that your available balance
covers the new withdrawal **plus every withdrawal still in progress** (each counted as amount + fee).
If it does not, the order is not created:

```json
{
  "error": "Insufficient merchant balance: 1200.00 PKR available, 2060.00 PKR required for this withdrawal and withdrawals in progress (including fees)."
}
```

Top up your balance, or wait for in-flight withdrawals to finish, then retry with a **new**
idempotency key. Deposit orders are not subject to this check.

## Rate limit errors

When an API key exceeds 100 requests per minute, the API returns `429 Too Many Requests` with
an empty body. Wait for the 60-second window to reset before retrying. See [Rate Limits](/rate-limits).

## No eligible member (422)

When no member is available for the requested wallet type and amount, the API returns `422`:

```json
{
  "success": false,
  "error": "No eligible member is currently available for this order.",
  "code": "NO_ELIGIBLE_MEMBER"
}
```

This is not a permanent failure — it means all members for this wallet type are offline or at capacity.
Wait a few minutes and retry with a new idempotency key.

## Recommended error handling

```javascript
async function createOrderSafe(params) {
  const response = await fetch('https://ca-c2c-dev-api.calmsea-c64629ed.uaenorth.azurecontainerapps.io/api/merchant/orders', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.C2C_API_KEY}`,
      'Idempotency-Key': params.idempotencyKey,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(params),
  });

  if (response.status === 429) {
    throw new Error('Rate limit hit — retry after 60 seconds');
  }

  if (!response.ok) {
    const error = await response.json();
    throw new Error(`${error.code}: ${error.error}`);
  }

  return response.json();
}
```
