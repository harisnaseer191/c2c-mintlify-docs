# Request Signing

In addition to your API key, every request to the C2C Merchant API must be **signed**.
Signing proves the request came from you, was not modified in transit, and is not a
replayed copy of an old request. A malformed, unsigned, or stale request is rejected
with `401 Unauthorized` before any business logic runs.

<Info>
  Your **signing secret** (`sksec_...`) is issued once, alongside your API key, when
  your admin generates or regenerates your merchant API key. Store it exactly like
  you store your API key — it is shown only once and cannot be retrieved again.
</Info>

## Headers

Every request must include these two headers in addition to your `Authorization` header:

| Header | Value | Description |
|--------|-------|--------------|
| `X-C2C-Timestamp` | Unix epoch seconds, e.g. `1750000000` | The time the request was signed |
| `X-C2C-Signature` | `sha256=<hex>` | HMAC-SHA256 of the canonical string, keyed with your signing secret |

## String to sign

Build the canonical string exactly as follows, joining the four parts with `\n` (newline):

```
{timestamp}\n{METHOD}\n{path}\n{hex(sha256(body))}
```

- `timestamp` — the same value sent in `X-C2C-Timestamp`
- `METHOD` — the HTTP method in uppercase, e.g. `POST`, `GET`
- `path` — the request path **and query string**, e.g. `/api/merchant/orders` or `/api/merchant/orders/{id}/status`
- `hex(sha256(body))` — the lowercase hex SHA-256 hash of the raw request body. For requests with no body (e.g. `GET`), hash an empty string.

Then compute:

```
signature = "sha256=" + hex(hmac_sha256(signing_secret, canonical_string))
```

Send `signature` as the `X-C2C-Signature` header value.

## Worked example (verify your implementation)

Use these fixed inputs to confirm your implementation produces the exact same signature
before calling the live API:

| Input | Value |
|-------|-------|
| Signing secret | `sksec_example_5f8b1c2d3e4f5a6b7c8d9e0f1a2b3c4d` |
| Timestamp | `1750000000` |
| Method | `POST` |
| Path | `/api/merchant/orders` |
| Body | `{"orderType":"Deposit","amount":1500,"currency":"PKR","walletType":"JazzCash","merchantOrderRef":"ORD-001"}` |

Expected intermediate and final values:

```
bodyHash  = 9d42e7e3b5305f385aa486aebd774f041570e07af31e8d41d87bc6c0300bdd88
canonical = 1750000000\nPOST\n/api/merchant/orders\n9d42e7e3b5305f385aa486aebd774f041570e07af31e8d41d87bc6c0300bdd88
signature = sha256=9439f71c99f229e9edfbfbb5464ffe1fb9b506061b6de9c55d52c88dcd4c18f6
```

If your code produces a different `signature` for these exact inputs, check the canonical
string construction first (most common bug is on the `path` or the body serialization).

## Signing a request

<CodeGroup>

```javascript Node.js
const crypto = require('crypto');

function signRequest(secret, method, path, body) {
  const timestamp = Math.floor(Date.now() / 1000);
  const bodyHash = crypto.createHash('sha256').update(body || '', 'utf8').digest('hex');
  const canonical = `${timestamp}\n${method.toUpperCase()}\n${path}\n${bodyHash}`;
  const signature = 'sha256=' + crypto.createHmac('sha256', secret).update(canonical).digest('hex');

  return {
    'X-C2C-Timestamp': String(timestamp),
    'X-C2C-Signature': signature,
  };
}

// Example: signing a POST /api/merchant/orders request
const body = JSON.stringify({ orderType: 'Deposit', amount: 1500.00, currency: 'PKR', walletType: 'JazzCash' });
const headers = {
  'Authorization': `Bearer ${process.env.C2C_API_KEY}`,
  'Content-Type': 'application/json',
  ...signRequest(process.env.C2C_SIGNING_SECRET, 'POST', '/api/merchant/orders', body),
};
```

```python Python
import hashlib
import hmac
import time


def sign_request(secret: str, method: str, path: str, body: str = "") -> dict:
    timestamp = str(int(time.time()))
    body_hash = hashlib.sha256(body.encode("utf-8")).hexdigest()
    canonical = f"{timestamp}\n{method.upper()}\n{path}\n{body_hash}"
    signature = "sha256=" + hmac.new(
        secret.encode("utf-8"), canonical.encode("utf-8"), hashlib.sha256
    ).hexdigest()

    return {"X-C2C-Timestamp": timestamp, "X-C2C-Signature": signature}

}
```

```php PHP
function signRequest(string $secret, string $method, string $path, string $body = ''): array {
    $timestamp = (string) time();
    $bodyHash = hash('sha256', $body);
    $canonical = "{$timestamp}\n" . strtoupper($method) . "\n{$path}\n{$bodyHash}";
    $signature = 'sha256=' . hash_hmac('sha256', $canonical, $secret);

    return [
        'X-C2C-Timestamp' => $timestamp,
        'X-C2C-Signature' => $signature,
    ];
}

// Example: signing a POST /api/merchant/orders request
$body = json_encode(['orderType' => 'Deposit', 'amount' => 1500.00, 'currency' => 'PKR', 'walletType' => 'JazzCash']);
$headers = array_merge(
    [
        'Authorization: Bearer ' . getenv('C2C_API_KEY'),
        'Content-Type: application/json',
    ],
    array_map(
        fn($k, $v) => "$k: $v",
        array_keys(signRequest(getenv('C2C_SIGNING_SECRET'), 'POST', '/api/merchant/orders', $body)),
        signRequest(getenv('C2C_SIGNING_SECRET'), 'POST', '/api/merchant/orders', $body)
    )
);
```

```csharp C#
using System.Security.Cryptography;
using System.Text;

static (string Timestamp, string Signature) SignRequest(string secret, string method, string path, string body = "")
{
    var timestamp = DateTimeOffset.UtcNow.ToUnixTimeSeconds().ToString();
    var bodyHash = Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(body))).ToLowerInvariant();
    var canonical = $"{timestamp}\n{method.ToUpperInvariant()}\n{path}\n{bodyHash}";
    var hash = Convert.ToHexString(
        HMACSHA256.HashData(Encoding.UTF8.GetBytes(secret), Encoding.UTF8.GetBytes(canonical))).ToLowerInvariant();

    return (timestamp, $"sha256={hash}");
}

// Example: signing a POST /api/merchant/orders request
var body = "{\"orderType\":\"Deposit\",\"amount\":1500.00,\"currency\":\"PKR\",\"walletType\":\"JazzCash\"}";
var (timestamp, signature) = SignRequest(Environment.GetEnvironmentVariable("C2C_SIGNING_SECRET")!, "POST", "/api/merchant/orders", body);
```

</CodeGroup>

<Warning>
  Compute the body hash from the **exact raw bytes** you send on the wire. If your HTTP
  client re-serializes or reformats the JSON body after you compute the signature, the
  signature will no longer match and the request will be rejected.
</Warning>

## Timestamp tolerance

Requests with a `X-C2C-Timestamp` more than **5 minutes** (300 seconds) away from the
server's clock are rejected as expired, even with a valid signature. This limits replay
attacks. Ensure your server's clock is synchronized (NTP).

## Troubleshooting a rejected request

If a request is rejected for signature reasons, the `401` response body includes a
`code` field and a `traceId` — quote the `traceId` when contacting support so the exact
request can be found in our logs:

```json
{
  "success": false,
  "error": "Request signature is missing, expired, or invalid.",
  "code": "SIGNATURE_INVALID",
  "traceId": "0af7651916cd43dd8448eb211c80319c"
}
```

| Code | Meaning | Fix |
|------|---------|-----|
| `SIGNATURE_REQUIRED` | `X-C2C-Timestamp` or `X-C2C-Signature` header is missing or malformed | Ensure both headers are present on every request |
| `SIGNATURE_EXPIRED` | The timestamp is outside the 5-minute tolerance | Sync your server clock and sign requests immediately before sending |
| `SIGNATURE_INVALID` | The API key is unknown/revoked, or the signature does not match | Verify you are using the current signing secret and the canonical string (method, path, and raw body) exactly matches what was sent |

<Note>
  During rollout, some environments may run signature checks in **log-only mode**
  (failures are recorded but requests are still accepted). Do not rely on this —
  fix rejected signatures as soon as they appear, since enforcement can be turned on
  at any time.
</Note>
