api: "GET /api/merchant/orders/{id}/status"
description: "Retrieve the current status, lifecycle stage and milestone timestamps of a deposit or withdrawal order, by its C2C orderId or orderReference, or by your own merchantOrderRef."
---

## Overview

Returns the current status, [lifecycle stage](/guides/order-status#lifecycle-stages) and milestone timestamps of one of **your merchant account's** orders. Use it to poll for the outcome, to reconcile after a missed webhook, or to confirm a webhook before you fulfil.

Lookups are scoped to your merchant account, not to an API key: any of your active API keys can query any of your orders, including orders created before a key rotation. You can look an order up by any of its identifiers. All of them return the same response:

| You have | Request |
|----------|---------|
| C2C's `orderId` | `GET /api/merchant/orders/{orderId}/status` |
| C2C's `orderReference` (`ORD-…`) | `GET /api/merchant/orders/{orderReference}/status` |
| Your own `merchantOrderRef` | `GET /api/merchant/orders/status?merchantOrderRef={merchantOrderRef}` ([see below](#query-by-merchantorderref)) |

| | |
|---|---|
| **API key** | Required |
| **Signature** | Not required. Read-only requests are authenticated by the API key alone. |

## Headers

<ParamField header="C2C-API-Key" type="string" required>
  `mk_live_...`, any of your merchant API keys. `Authorization: Bearer mk_live_...` is also accepted.
</ParamField>

## Path parameters

<ParamField path="id" type="string" required>
  Either of C2C's identifiers for the order, both returned by [Create deposit](/api-reference/endpoints/create-deposit) or [Create withdrawal](/api-reference/endpoints/create-withdrawal) and present in webhooks:

  - the `orderId`, for example `788fcae0-5214-403c-baa2-f318c0eb1b5b`
  - the `orderReference`, for example `ORD-20261008120620-3f6b`

  To look an order up by your own reference, use [Query by `merchantOrderRef`](#query-by-merchantorderref).
</ParamField>

```javascript Node.js
const BASE_URL = 'https://ca-c2c-dev-api.calmsea-c64629ed.uaenorth.azurecontainerapps.io';

// Pass exactly one identifier: C2C's orderId or orderReference, or your merchantOrderRef.
async function getOrderStatus({ orderId, orderReference, merchantOrderRef }) {
  const path = merchantOrderRef
    ? `/api/merchant/orders/status?merchantOrderRef=${encodeURIComponent(merchantOrderRef)}`
    : `/api/merchant/orders/${encodeURIComponent(orderId ?? orderReference)}/status`;
  const response = await fetch(`${BASE_URL}${path}`, {
    headers: { 'C2C-API-Key': process.env.C2C_API_KEY },
  });
  if (!response.ok) throw new Error(`Status query failed: HTTP ${response.status}`);
  return (await response.json()).data;
}

await getOrderStatus({ orderId: '788fcae0-5214-403c-baa2-f318c0eb1b5b' });
await getOrderStatus({ orderReference: 'ORD-20261008120620-3f6b' });
await getOrderStatus({ merchantOrderRef: 'INV-10045' });
```

## Status values

| Status | Applies to | Meaning | Final? |
|--------|-----------|---------|--------|
| `Awaiting` | Both | Accepted, waiting for an eligible member. Deposit: a member is assigned when the customer opens the payment page; if none is assigned before the checkout link expires (15 minutes), it ends `CancelledTimeout`. Withdrawal: assigned automatically as soon as a member is available, or `CancelledTimeout` after 120 minutes. | No |
| `Queued` | Deposit | Created with a member assigned. The customer hasn't chosen a wallet on the payment page yet. | No |
| `AwaitingCustomerPayment` | Deposit | Wallet chosen and account shown. Waiting for the customer to pay and submit the transaction digits. | No |
| `AwaitingMemberConfirmation` | Deposit | Customer submitted payment. Waiting for the member to verify receipt. | No |
| `AwaitingMemberPayout` | Withdrawal | Waiting for the member to send the payout. | No |
| `ManualReview` | Both | Escalated to C2C operations, for example a member confirmation or payout window passed. Resolved by C2C to `Completed` or `Cancelled`, which sends `order.completed` or `order.failed`. Stage `Sent` if the customer had already paid, otherwise `Assigned`. | No |
| `Completed` | Both | **Success.** Funds received (deposit) or paid out (withdrawal). | **Yes, success** |
| `Rejected` | Both | The member rejected the order, for example because no matching payment was received. | **Yes, failed** |
| `Expired` | Deposit | The checkout link (15 minutes) expired before the customer paid, including when they never opened it. | **Yes, failed** |
| `CancelledTimeout` | Both | No eligible member became available in time (`Awaiting` order timed out). | **Yes, failed** |
| `Cancelled` | Both | Cancelled by C2C or the member. | **Yes, failed** |
| `CancelledAuto` | Both | Cancelled automatically by the system. | **Yes, failed** |

<Accordion title="Legacy statuses (older orders only)">
  Orders created by earlier versions of the platform can also report `Assigned` (in progress), `Frozen` (in progress, past the member's freeze window) and `Confirmed` (**success**, equivalent to `Completed`). Treat `Confirmed` as success if you see it.
</Accordion>

<Warning>
  Fulfil a deposit or record a payout **only** on `Completed` (or legacy `Confirmed`). `ManualReview` isn't a failure: don't refund or re-pay the customer until C2C resolves the order.
</Warning>

## Polling guidelines

- Prefer [webhooks](/guides/webhooks) and poll as a fallback or to reconcile.
- Poll every **5–10 seconds** while the customer is on the payment page, then back off (for example every minute) for orders waiting on a member.
- Stop polling once the status is final.
- The Merchant API has no request rate limits, but don't poll many orders in tight loops; webhooks scale better.
- `ManualReview` sends no webhook until C2C resolves it, so poll those orders at a low frequency until they are final.
- You can branch on `stage` instead of `status`: `Completed` is success, `Failed` is final without settlement, anything else is in progress.

```javascript Node.js
const FINAL = new Set(['Completed', 'Confirmed', 'Rejected', 'Expired', 'CancelledTimeout', 'Cancelled', 'CancelledAuto']);
const SUCCESS = new Set(['Completed', 'Confirmed']);

// lookup: { orderId }, { orderReference } or { merchantOrderRef }, as for getOrderStatus above
async function waitForOutcome(lookup, { intervalMs = 5000, timeoutMs = 30 * 60 * 1000 } = {}) {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    const { status } = await getOrderStatus(lookup);
    if (FINAL.has(status)) return { status, success: SUCCESS.has(status) };
    await new Promise((r) => setTimeout(r, intervalMs));
  }
  return { status: 'Pending', success: false }; // keep reconciling later
}
```

## Error responses

| Status | When | Body |
|--------|------|------|
| `401` | API key missing, invalid or revoked | Empty body |
| `404` | No order with this `orderId` or `orderReference` for your merchant account | `{"error": "Order not found."}` |

## Query by `merchantOrderRef`

```http
GET /api/merchant/orders/status?merchantOrderRef={merchantOrderRef}
```

Returns the **latest** order your merchant account created with this `merchantOrderRef`, in exactly the same response shape as above. Use it to track orders by your own reference, or when you didn't get the `orderId` back, for example after a timeout. Authentication works the same as for the lookup by ID: API key only, no signature.

<ParamField query="merchantOrderRef" type="string">
  Your `merchantOrderRef` from order creation. URL-encode it.
</ParamField>

<ParamField query="orderReference" type="string">
  C2C's `orderReference` (`ORD-…`). Accepted here too, as an alternative to the path form above.
</ParamField>

Send **one** of the two parameters.

```bash cURL
curl --request GET \
  --url "https://ca-c2c-dev-api.calmsea-c64629ed.uaenorth.azurecontainerapps.io/api/merchant/orders/status?merchantOrderRef=INV-10045" \
  --header "C2C-API-Key: $C2C_API_KEY"
```

```javascript Node.js
const order = await getOrderStatus({ merchantOrderRef: 'INV-10045' });   // helper from the examples above
```

| Status | When | Body |
|--------|------|------|
| `400` | Neither parameter sent, or both empty | `{"error": "Provide an orderId, an orderReference or a merchantOrderRef."}` |
| `400` | Both `merchantOrderRef` and `orderReference` sent | `{"error": "Provide either an orderReference or a merchantOrderRef, not both."}` |
| `401` | API key missing, invalid or revoked | Empty body |
| `404` | No order with this reference for your merchant account | `{"error": "Order not found."}` |

<Note>
  A `merchantOrderRef` can belong to several orders only when the earlier ones failed (see [`merchantOrderRef` rules](/guides/order-status#merchantorderref-rules)). This endpoint always returns the most recent one; use the `orderId` or `orderReference` to query an older order.
</Note>
