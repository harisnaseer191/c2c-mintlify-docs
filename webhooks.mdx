# Webhooks

The C2C Platform delivers signed HTTP callbacks to a URL you provide when creating an order.
Set `callbackUrl` in your `POST /api/merchant/orders` request and your endpoint receives a
`POST` with the order result as soon as it is resolved.

## How it works

1. Include `callbackUrl` in your order creation request
2. When the order completes or fails, the platform `POST`s a signed JSON payload to your URL
3. Your endpoint verifies the HMAC-SHA256 signature and processes the event
4. If your endpoint does not respond with `2xx`, the platform retries with exponential backoff

## Setting a callback URL

```json
{
  "orderType": "Deposit",
  "amount": 1500.00,
  "currency": "PKR",
  "walletType": "JazzCash",
  "merchantOrderRef": "ORD-001",
  "callbackUrl": "https://yoursite.com/webhooks/c2c"
}
```

<Warning>
  `callbackUrl` must be an absolute `http://` or `https://` URL (max 500 characters) reachable
  from the internet — any other scheme is rejected with `400`. Use **HTTPS** in production.
  The platform does not retry unreachable hosts indefinitely — ensure your server is available.
</Warning>

## Event types

| Event | Trigger |
|-------|---------|
| `order.completed` | Order confirmed successfully — safe to fulfil the purchase |
| `order.failed` | Order rejected, cancelled, or expired — do not fulfil |

## Webhook payload

### order.completed

```json
{
  "eventType": "order.completed",
  "orderId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "orderReference": "C2C-20260618-001234",
  "merchantOrderRef": "ORD-001",
  "amount": 1500.00,
  "currency": "PKR",
  "status": "Completed",
  "completedAt": "2026-06-18T14:35:22Z",
  "timestamp": "2026-06-18T14:35:22Z"
}
```

### order.failed

```json
{
  "eventType": "order.failed",
  "orderId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "orderReference": "C2C-20260618-001234",
  "merchantOrderRef": "ORD-001",
  "amount": 1500.00,
  "currency": "PKR",
  "status": "Rejected",
  "reason": "Member did not receive payment.",
  "timestamp": "2026-06-18T14:40:00Z"
}
```

### Payload fields

| Field | Type | Notes |
|-------|------|-------|
| `eventType` | string | `order.completed` or `order.failed` (same value as the `X-C2C-Event` header) |
| `orderId` | string (UUID) | The `orderId` returned when you created the order |
| `orderReference` | string | Platform-generated order reference |
| `merchantOrderRef` | string \| null | Your own reference, if you sent one |
| `amount` | number | Order amount |
| `currency` | string | ISO currency code, e.g. `"PKR"` |
| `status` | string | Order status at the time of the event, e.g. `Completed`, `Rejected`, `Expired` |
| `completedAt` | string (UTC) | `order.completed` only — when the order was confirmed |
| `reason` | string | `order.failed` only — why the order failed |
| `timestamp` | string (UTC) | When the event was generated. Stays the same on every retry of the same event |

## Verifying the signature

Every webhook request includes these headers:

| Header | Value |
|--------|-------|
| `X-C2C-Signature` | `sha256=<hmac-sha256-hex>` |
| `X-C2C-Event` | `order.completed` or `order.failed` |
| `X-C2C-Key-Prefix` | The key prefix of the API key whose secret signed this webhook — the 8 characters right after `mk_live_` (e.g. `a1b2c3d4` for `mk_live_a1b2c3d4...`) |

The signature is an HMAC-SHA256 of the **raw request body**, keyed with your **API key's
signing secret** (`sksec_...`) — the same secret you use to [sign API requests](/signing).
No separate webhook secret is needed.

Which key signs a webhook:

- The API key that **created the order**, while that key is still active
- If that key has since been revoked or rotated, your merchant account's **newest active key**

`X-C2C-Key-Prefix` tells you which key was used, so during a key rotation you can look up
the matching secret instead of trying each one.

<Note>
  Every attempt is re-signed with the current secret, so a retry of a webhook first sent before
  a key rotation is signed with your **new** key's secret. Keep the new secret deployed before
  revoking the old key.
</Note>

<Note>
  Legacy API keys issued without a signing secret receive webhooks signed with a platform-wide
  secret and without the `X-C2C-Key-Prefix` header. Ask your C2C admin to regenerate the key to
  move to per-merchant signing.
</Note>

**Verification examples**

<CodeGroup>

```javascript Node.js
const crypto = require('crypto');

function verifyWebhook(rawBody, signatureHeader, signingSecret) {
  const expected = 'sha256=' + crypto
    .createHmac('sha256', signingSecret)
    .update(rawBody, 'utf8')
    .digest('hex');

  return crypto.timingSafeEqual(
    Buffer.from(signatureHeader),
    Buffer.from(expected)
  );
}

// Express example
app.post('/webhooks/c2c', express.raw({ type: 'application/json' }), (req, res) => {
  const signature = req.headers['x-c2c-signature'];
  if (!verifyWebhook(req.body, signature, process.env.C2C_SIGNING_SECRET)) {
    return res.status(401).send('Invalid signature');
  }

  const event = JSON.parse(req.body);
  if (event.eventType === 'order.completed') {
    // Fulfil the order
  }

  res.sendStatus(200);
});
```

```python Python
import hmac, hashlib

def verify_webhook(raw_body: bytes, signature_header: str, signing_secret: str) -> bool:
    expected = 'sha256=' + hmac.new(
        signing_secret.encode(), raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(signature_header, expected)

# Flask example
from flask import Flask, request, abort
import os, json

app = Flask(__name__)

@app.route('/webhooks/c2c', methods=['POST'])
def webhook():
    raw_body = request.get_data()
    signature = request.headers.get('X-C2C-Signature', '')
    if not verify_webhook(raw_body, signature, os.environ['C2C_SIGNING_SECRET']):
        abort(401)

    event = json.loads(raw_body)
    if event['eventType'] == 'order.completed':
        pass  # fulfil order

    return '', 200
```

```php PHP
function verifyWebhook(string $rawBody, string $signatureHeader, string $signingSecret): bool {
    $expected = 'sha256=' . hash_hmac('sha256', $rawBody, $signingSecret);
    return hash_equals($expected, $signatureHeader);
}

$rawBody = file_get_contents('php://input');
$signature = $_SERVER['HTTP_X_C2C_SIGNATURE'] ?? '';

if (!verifyWebhook($rawBody, $signature, getenv('C2C_SIGNING_SECRET'))) {
    http_response_code(401);
    exit;
}

$event = json_decode($rawBody, true);
if ($event['eventType'] === 'order.completed') {
    // fulfil order
}

http_response_code(200);
```

</CodeGroup>

<Warning>
  Always verify the signature **before** reading or acting on the payload.
  Use a constant-time comparison (`timingSafeEqual`, `hmac.compare_digest`, `hash_equals`)
  to prevent timing attacks.
</Warning>

## Retry behaviour

If your endpoint returns a non-`2xx` status code or is unreachable, the platform retries the
**same delivery** using exponential backoff. A delivery is attempted at most **10 times** in total
(the first attempt plus up to 9 retries):

| After failed attempt | Next attempt in |
|----------------------|-----------------|
| 1 | 60 s |
| 2 | 2 min |
| 3 | 4 min |
| 4 | 8 min |
| 5 | 16 min |
| 6 | 32 min |
| 7 | ~64 min |
| 8 | ~2 h 8 min |
| 9 | ~4 h 16 min |
| 10 | — abandoned |

Each retry sends the **identical JSON body** (including the original `timestamp`), re-signed with
the current signing secret. Retries are checked periodically, so an attempt may arrive shortly
after the time shown. After the 10th failed attempt the delivery is abandoned — use
[polling](#polling-as-a-fallback) to reconcile any order you did not receive a webhook for.

## Best practices

- **Respond immediately** — return `200` as soon as you validate the signature, then process asynchronously
- **Make your handler idempotent** — the same event may be delivered more than once due to retries; deduplicate on `orderId` + `eventType`
- **Use `merchantOrderRef`** — set a unique reference per order so your handler can locate the record quickly
- **Check `status`** — never fulfil on `order.failed`, even if `eventType` is unexpected

## Polling as a fallback

If you cannot host a public HTTPS endpoint, omit `callbackUrl` and poll
`GET /api/merchant/orders/{id}/status` every 3–5 seconds instead.
See the [Server Integration guide](/guides/server-integration) for a complete polling implementation.
