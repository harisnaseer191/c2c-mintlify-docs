---

## Overview

Creates a **deposit**: your customer pays money into an account held by a C2C member, and the amount, minus fees, is credited to your merchant wallet once the member confirms receipt.

C2C assigns an available member when the order is created and returns a `paymentPageUrl`. Redirect your customer to that hosted page. There they pick their wallet, see the account to pay, send the money from their wallet app, and enter the last digits of the transaction ID. See the [Deposit flow](/guides/deposit-flow) for the full lifecycle.

The order is **always accepted**. If no eligible member is available right now, it's created with status `Awaiting`, and a member is assigned when the customer picks a wallet on the payment page.

| | |
|---|---|
| **API key** | Required |
| **Signature** | **Required**, in the body's `signature` field. See the [Signature Generation Guide](/api-reference/signature-guide) |
| **Idempotency-Key** | Required |

<Info>
  Deposits and withdrawals use the same endpoint. Set `orderType` to `"Deposit"` to create a deposit.
</Info>

## Headers

<ParamField header="C2C-API-Key" type="string" required>
  `mk_live_...`, your merchant API key. `Authorization: Bearer mk_live_...` is also accepted.
</ParamField>

<ParamField header="Idempotency-Key" type="string" required>
  Your unique key for this order attempt, up to 100 characters. Retrying with the same key returns the original order instead of creating a new one. See [Idempotency](/api-reference/idempotency).
</ParamField>

<ParamField header="Content-Type" type="string" required>
  `application/json`
</ParamField>

## Request body

<ParamField body="orderType" type="string" required>
  Must be `"Deposit"`.
</ParamField>

<ParamField body="amount" type="number" required>
  Amount the customer pays, in `currency`. Must be greater than `0`, have at most 4 decimal places and be less than `100,000,000,000,000`.

  **Example:** `1500`
</ParamField>

<ParamField body="walletType" type="string" required>
  The wallet the customer intends to pay with. C2C uses it to assign a member with a matching account. The customer can still switch to another wallet that is enabled for you on the payment page.

  One of `JazzCash`, `Easypaisa`, `TillID`, `BankAccount`.
</ParamField>

<ParamField body="currency" type="string" default="PKR">
  ISO currency code: `PKR`, `INR` or `BDT`. Defaults to `PKR`.
</ParamField>

<ParamField body="merchantOrderRef" type="string">
  Your own reference for this order, such as an invoice or cart ID. Up to 200 characters. It is echoed in [webhooks](/guides/webhooks), and you can [query the order by it](/api-reference/endpoints/query-order-status#query-by-merchantorderref).

  <Note>
    One live order per reference: if an order that is in progress or completed already uses this `merchantOrderRef`, the request is rejected with `409`. A reference whose earlier order failed can be reused. To retry a request, reuse the same `Idempotency-Key` instead. See [`merchantOrderRef` rules](/guides/order-status#merchantorderref-rules).
  </Note>
</ParamField>

<ParamField body="customerReference" type="string">
  Your identifier for the paying customer, for example a player ID. Up to 200 characters.
</ParamField>

<ParamField body="callbackUrl" type="string">
  Absolute `http(s)` URL that receives the `order.completed` / `order.failed` [webhooks](/guides/webhooks) for this order. Up to 500 characters. It must resolve to a public internet address: loopback, private and link-local addresses are refused at delivery time, and redirects aren't followed.

  If omitted, C2C uses the default callback URL set in your **Merchant Portal → Settings**. If neither is set, no webhook is sent and you must poll [order status](/api-reference/endpoints/query-order-status).
</ParamField>

<ParamField body="successUrl" type="string">
  Absolute `http(s)` URL, up to 500 characters. When the order completes, the hosted payment page sends the customer here, with `c2c_order_id`, `c2c_order_reference` and `c2c_status` appended. See [Returning the customer](/guides/hosted-payment-page#returning-the-customer-to-your-site).
</ParamField>

<ParamField body="failureUrl" type="string">
  Absolute `http(s)` URL, up to 500 characters. Where the hosted payment page sends the customer when the order is rejected, expires or is cancelled. The same parameters are appended.
</ParamField>

<ParamField body="metadata" type="string">
  Free-form string, for example JSON-encoded, stored with the order for reconciliation. Up to 1000 characters. It isn't returned in API responses or webhooks.
</ParamField>

<ParamField body="txnRefDigitsRequired" type="integer" default="4">
  How many trailing digits of the wallet transaction ID the customer must enter on the payment page. `4` to `8`.
</ParamField>

<ParamField body="maxRetryCount" type="integer" default="3">
  `0` to `10`. Only used by withdrawals: it limits how often C2C reassigns an order to another member. It has no effect on deposits.
</ParamField>

<ParamField body="signature" type="string" required>
  32-character lowercase hex MD5 of the other top-level fields (lowercased keys in ASCII order, `key=value` joined with `&`, `null` and empty values skipped) followed directly by your signing secret. See the [Signature Generation Guide](/api-reference/signature-guide).

  **Example:** `f2eb65603d36507621fdfd64aba78974`
</ParamField>

## Response

<ResponseField name="data" type="object">
  <Expandable title="properties" defaultOpen>
    <ResponseField name="orderId" type="uuid">
      C2C's unique order ID. **Store it.** You need it for [status queries](/api-reference/endpoints/query-order-status), and it is the `orderId` in webhooks.
    </ResponseField>
    <ResponseField name="paymentPageUrl" type="string">
      Hosted payment page for this order. Redirect the customer here. The URL is pre-signed and stops working at `expiresAt`. Don't modify it, and don't expose it to anyone other than the paying customer.
    </ResponseField>
    <ResponseField name="status" type="string">
      Initial status: `Queued` when a member was assigned, or `Awaiting` when no eligible member was available yet. See [Order status](/guides/order-status).
    </ResponseField>
    <ResponseField name="stage" type="string">
      Lifecycle stage: `Assigned` or `Awaiting` for a new deposit. See [Lifecycle stages](/guides/order-status#lifecycle-stages).
    </ResponseField>
    <ResponseField name="merchantOrderRef" type="string | null">
      Your `merchantOrderRef`, or `null` if you didn't send one.
    </ResponseField>
    <ResponseField name="orderReference" type="string">
      C2C's human-readable reference, for example `ORD-20261008120620-3f6b`. Quote it to support.
    </ResponseField>
    <ResponseField name="expiresAt" type="string">
      ISO 8601 UTC time when the payment page link expires, **15 minutes** after creation.
    </ResponseField>
  </Expandable>
</ResponseField>

## Error responses

| Status | When | Body |
|--------|------|------|
| `400` | A field fails validation, for example amount ≤ 0, an amount with more than 4 decimal places or too large, an unknown currency, an invalid URL or a value that is too long | `{"error": "..."}`. Multiple messages are joined with `; ` |
| `400` | `Idempotency-Key` missing, malformed JSON, or an unknown `orderType`/`walletType` value | `application/problem+json` with an `errors` object |
| `401` | API key missing, invalid or revoked | Empty body |
| `401` | `signature` missing, malformed, invalid, or replayed under a different `Idempotency-Key` | `{"success": false, "error", "code", "traceId"}` |
| `403` | Merchant account not active, or caller IP not whitelisted | `{"error": "..."}` |
| `413` | Body larger than 64 KB | `{"success": false, "error", "code": "PAYLOAD_TOO_LARGE", "traceId"}` |
| `409` | `merchantOrderRef` is already used by an order that is in progress or completed | `{"error": "merchantOrderRef '...' is already used by order ORD-…. ..."}` |
| `422` | The wallet channel is disabled for your account: `JazzCash deposits are disabled for this merchant.` | `{"error": "..."}` |
| `422` | The `Idempotency-Key` was already used with different order terms | `{"error": "This Idempotency-Key was already used for a different order request."}` |

See [Errors](/api-reference/errors) for the complete error model.

<Tip>
  If a request was rejected (`400`, `409`, `422` …), you can fix it and reuse the same `Idempotency-Key`, because rejected requests don't consume the key.
</Tip>

## What happens next

1. Redirect the customer to `paymentPageUrl` **immediately**. The link expires after 15 minutes.
2. If the order is `Awaiting`, a member is assigned when the customer picks a wallet. Until one is online the page shows "Finding an available agent…" and re-checks every 10 seconds.
3. The customer pays and submits the transaction digits. The order moves to `AwaitingCustomerPayment` and then `AwaitingMemberConfirmation`.
4. The member confirms (`Completed`) or rejects (`Rejected`) the payment.
5. You receive a [webhook](/guides/webhooks), and you can [query the status](/api-reference/endpoints/query-order-status) at any time. If you set `successUrl` / `failureUrl`, the payment page sends the customer back to you.

<Warning>
  Fulfil the purchase only when the order status is `Completed`, never on the creation response.
</Warning>
