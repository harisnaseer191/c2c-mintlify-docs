# Idempotency

The `POST /api/merchant/orders` endpoint requires an `Idempotency-Key` header.
This lets you safely retry failed requests without creating duplicate orders.

## How it works

Idempotency keys are scoped to the **API key** that sends the request. When you send a
request with an `Idempotency-Key`:

1. If the key is **new** for your API key, the order is created and the key is linked to it
2. If the key was **already used**, no new order is created — the response is the **original
   order** (same `orderId`, `orderReference` and `paymentPageUrl`) with its **current** `status`,
   returned as a normal `200`

The request body of a repeated key is not compared with the original: the original order is
always returned. Never reuse a key for a different order.

### Concurrent requests

If two requests with the same `Idempotency-Key` arrive at the same time (for example, a
client-side timeout followed by an immediate retry), only **one** order is created. Both
requests receive that same order in their response.

## Sending the header

```http
POST /api/merchant/orders HTTP/1.1
Authorization: Bearer mk_live_your_api_key
Idempotency-Key: order_player_12345_20260519_001
X-C2C-Timestamp: 1750000000
X-C2C-Signature: sha256=...
Content-Type: application/json
```

A request without the header is rejected with `400`:

```json
{ "error": "Idempotency-Key header is required." }
```

## Key format recommendations

Use a key that uniquely identifies your intent — not just a random UUID:

```javascript
// Good: combines your order reference and customer
const idempotencyKey = `order_${customerId}_${yourInternalOrderId}`;

// Also fine: a UUID generated once per checkout attempt
const idempotencyKey = crypto.randomUUID();
```

<Warning>
  Generate the key **once** per order attempt and persist it in your database
  before sending the request. If you generate a new key on each retry, you will
  create duplicate orders.
</Warning>

## Key lifetime

Keys do **not** expire. Once used, a key always returns the order it created, so
always use a new key for a new order. Keys are tied to the API key that sent them —
after your API key is regenerated, keys sent with the new API key start fresh.

## Retries must be re-signed

Every `POST` signature is accepted only once (see [Replay protection](/signing#replay-protection)).
When retrying, keep the **same** `Idempotency-Key` and body, but compute a **fresh**
`X-C2C-Timestamp` and `X-C2C-Signature` for each attempt. Resending the exact same signed
request is rejected with `401 SIGNATURE_REPLAYED`.

## Safe retry pattern

```javascript
async function createOrderWithRetry(params, maxAttempts = 3) {
  // Generate the idempotency key ONCE and store it before the first attempt
  const idempotencyKey = `order_${params.customerId}_${params.internalOrderId}`;
  const body = JSON.stringify(params);

  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    let response;
    try {
      response = await fetch('https://ca-c2c-dev-api.calmsea-c64629ed.uaenorth.azurecontainerapps.io/api/merchant/orders', {
        method: 'POST',
        headers: {
          'Authorization': `Bearer ${process.env.C2C_API_KEY}`,
          'Idempotency-Key': idempotencyKey,  // same key on every retry
          'Content-Type': 'application/json',
          // fresh timestamp + signature on every attempt — see /signing
          ...signRequest(process.env.C2C_SIGNING_SECRET, 'POST', '/api/merchant/orders', body),
        },
        body,
      });
    } catch (networkError) {
      // Timeout / connection reset: the order may or may not exist — retrying with the same key is safe
      if (attempt === maxAttempts) throw networkError;
    }

    if (response) {
      // 200 = created now, or the order an earlier attempt with this key already created
      if (response.ok) return response.json();

      // 4xx (other than 429) will not succeed on retry — surface it
      if (response.status < 500 && response.status !== 429) {
        const error = await response.json();
        throw new Error(error.error);
      }
    }

    if (attempt < maxAttempts) await new Promise(r => setTimeout(r, 1000 * 2 ** attempt));
  }
  throw new Error('Order creation failed after retries');
}
```
